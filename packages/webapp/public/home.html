A BlitzOS workspace: the session rail, an agent session, and its diff, in the browser.

The frontier moves monthly. Your company can too.

AI capability improves faster than companies adopt it. BlitzOS closes that gap in three ways.

Test the frontier

Run a new model on real work, in a workspace that already has the repos, credentials, and agent rules in place.

Ship setups to everyone

Get one workspace right. Invite the team, and every member gets their own machine with the same agent, rules, and repos.

Keep control of access

Each workspace sets the providers its agents may reach. Tokens are minted on request against that list, and they expire.

Set up one workspace. Hand it to the whole team.

A workspace holds the setup for one kind of work: repos, agent rules, connections, credentials, and machine type. Add a teammate and they get their own machine with that same setup. Need a variation? Create a new workspace from an existing one. It carries the machine type, the agent rules, the repos, and the connection allow-list.

A sandboxed computer for every member.

Every member of a workspace gets their own cloud machine, with Linux and Docker inside, holding only the credentials and data that job needs. Claude Code and Codex come installed. Any other CLI agent installs on top. Run as many machines at once as the work needs, independent of any local dev setup. Watch the work from the browser, the terminal, or SSH.

Share the workspace. Skip the setup work.

Add a teammate to a workspace and they get their own machine, already holding the same repos, the same agent rules, and the same connections. Their provider tokens are minted for them, never handed over. Add someone as a viewer and they read the workspace without using a machine at all.

And the rest of the OS.

▦

Teenyapps. Agents build internal tools in a workspace: dashboards, CRMs, task managers. Preview one on its live port, then keep the deployed link beside it.

⌁

Connections. GitHub, Google Workspace, Linear, Discord, and YouTrack. Each member connects their own account, or an admin holds one credential for the organization.

▲

Agent Drive. Upload a file once. Attach it to any workspace, or share it with any teammate. Edits sync both ways.

✓

Usage capture. Turn it on and real agent sessions land in a Drive folder, ready to become an eval suite.

⌘

Machine API. An agent inside a workspace lists the workspaces its member reaches, then starts, stops, or recreates machines there and connects over SSH. It cannot add members or workspaces, or reach past its member's role.

◇

Bring your own agent. Claude Code and Codex come installed. Any other CLI agent installs on top, on your existing billing plan.

☁

Bring your own cloud. Hetzner, AWS, and your own Firecracker hosts are built in. Any other cloud is one VmProvider implementation.
